Multi-Agent Workflow Patterns

Four ways to wire agents together, shown against SAP Sales & Distribution processes. Press Run on any card to watch a sales document move through that pattern.

Sequential Handoff

Sales Order agent → Delivery agent → Billing agent

Each agent completes its SD document and hands the structured output to the next stage — order creation, outbound delivery, then invoice — mirroring the standard Order-to-Cash document flow (VA01 → VL01N → VF01).

Parallel Fan-Out / Fan-In

Credit, ATP, and tax agents check the order at once → release agent merges

Three checks that don't depend on each other — credit exposure, stock availability, and tax determination — run simultaneously the moment a sales order is saved; a release agent merges the results and confirms or blocks it.

Manager–Worker Delegation

Order Processing Manager routes incoming SD documents by type

A manager agent reads the incoming document type and dynamically routes it to the specialist worker built for that flow — standard order, return, or credit memo — based on current load, not a fixed rule.

Debate & Consensus

Warranty and fraud-signal agents assess independently → RMA judge decides

Two agents evaluate the same return request from different angles — warranty policy compliance and fraud/abuse signals — then a judge agent approves or denies the return material authorization (RE → CR).

Each pattern trades off speed, cost, and reliability differently — sequential mirrors the standard O2C document flow, parallel speeds up order validation, manager–worker adapts to document type and load, and debate&consensus spends extra compute to reconcile a disputed return decision.
